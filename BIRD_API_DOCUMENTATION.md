# Bird API Documentation (api-bird.prod.birdapp.com)

Reverse-engineered from Bird Android APK (jadx decompilation) with exported network logs, useing nvidia_nim/nvidia/nemotron-3-ultra-550b-a55b proxyied through claude code

## Base URL

**Production**: `https://api-bird.prod.birdapp.com/`

- Service: `api-bird` (g5e.d = API_BIRD, port 8080)
- Constructed dynamically via `AppPreference.O0(g5e)` using string format: `https://%s.prod.birdapp.com/`

## Authentication

### Authorization Header Format
```
Authorization: Bearer <access_token>
```

**Note**: Uses `Bearer` prefix (standard JWT), NOT `Bird`. The token is a JWT (JSON Web Token) with RS512 algorithm. This was confirmed from actual network traffic (chucker exports) - the decompiled code suggested "Bird" prefix but real traffic uses "Bearer".

### JWT Token Details
From chucker exports, the JWT contains:
- Algorithm: RS512 (`"alg":"RS512"`)
- Claims: `jti`, `sub` (user ID), `nbf`, `exp`, `aud` ("bird.services"), `iss` ("bird.auth"), `iat`, `roles` (["USER"]), `app` (app ID), `ver` ("0.0.2")

### Token Management
- Access tokens and refresh tokens stored as `TokenPair`
- Token exchange/refresh handled via `ly0` interface (Auth API)
- Interceptor (`ry0`) automatically adds Authorization header to endpoints marked with `@muk` annotation

## Pagination

The API uses two pagination patterns:

### 1. PagedCollection<T>
Used for offset/limit pagination with total count:
```kotlin
data class PagedCollection<T>(
    @Json(name = "total") val total: Int,
    @Json(name = "offset") val offset: Int,
    @Json(name = "limit") val limit: Int,
    @Json(name = "items") val items: List<T>
)
```
- `total` - Total number of items across all pages
- `offset` - Current page offset (0-based)
- `limit` - Page size (items per page)
- `items` - List of items for current page

### 2. CollectionResponse<T>
Alternative pagination with hasMore() helper:
```kotlin
class CollectionResponse<T>(
    @Json(name = "total") val total: Int,
    @Json(name = "offset") val offset: Int,
    @Json(name = "items") val items: List<T>
) {
    fun hasMore(): Boolean = offset + items.size < total
}
```
- Same fields but no explicit limit field
- `hasMore()` method indicates if more pages exist

**Usage**: Query parameters typically use `offset` and `limit` (e.g., `GET /user/transaction-history?offset=0&limit=20`)

- No standard HTTP rate limit headers (X-RateLimit-*) observed in decompiled code

## Token Management (i01 / sz0 Implementation)

### TokenPair
```kotlin
data class TokenPair(
    val accessJwt: JWT,      // Short-lived access token
    val refreshJwt: JWT      // Long-lived refresh token
)
```

### TokenPairState
```kotlin
data class TokenPairState(
    val tokenPair: TokenPair,
    val refreshRequested: Boolean  // Prevents concurrent refresh attempts
)
```

### Token Refresh Logic (i01)
1. **Expiration Check**: Access token considered expired if `exp` within 600 seconds (10 min)
2. **Automatic Refresh**: On 401 for @muk-annotated endpoints, interceptor triggers refresh
3. **Refresh Flow**:
   - If valid refresh token → Call `POST /api/v1/auth/refresh/token` with `Authorization: Bearer <refresh_token>`
   - If no refresh token or expired → Clear tokens, require re-auth
4. **Thread Safety**: Uses `ReentrantReadWriteLock` for concurrent access
5. **Reactive Streams**: Returns `Single`, `Completable`, `Maybe` for async operations

### Supported Auth Header Formats
The token manager (`i01`) supports both:
- `Bearer <token>` - **Used for API calls** (standard JWT, confirmed via chucker)
- `Bird <token>` - Legacy format (found in code but not used in production traffic)

## Authentication Interceptor (ry0)

The `ry0` OkHttp interceptor handles:
1. **Auto-adds Authorization header** for endpoints marked with `@muk` annotation
2. **401 Handling**: 
   - If endpoint has `@muk` → Emits event for token refresh, retries request
   - If no `@muk` → Throws `AuthRejectionException`
3. **Token Source**: Gets tokens from `sz0` (implemented by `i01`)

## Error Handling

### AuthRejectionException
```kotlin
class AuthRejectionException(request: Request) : RuntimeException(
    "${request.method} ${request.url} could not be performed due to: AuthError.Rejected"
)
```
- Thrown when 401 received on non-@muk endpoints
- Contains original request for debugging

### RxJava3 Error Types
- `Single` - Single value or error
- `Observable` - Multiple values or error  
- `Completable` - Completion or error (no value)
- `Maybe` - Single value, empty, or error
- `Flowable` - Backpressure-aware stream

### HTTP Errors
- Standard Retrofit `HttpException` for non-2xx responses
- No custom error response body format documented in decompiled code

## Retry Logic

**No automatic retry for API calls** found in decompiled code. The only retry logic observed:
- BLE/connection suspension retry (ReactiveLocationProvider)
- WorkManager backoff policies (Android system)

## Notes for Bug Bounty Testing

1. **Authentication**: All operator endpoints require `Authorization: Bearer <token>`
2. **Token Format**: JWT with "Bearer " prefix (standard JWT, not Bird)
3. **Base URL**: `https://api-bird.prod.birdapp.com/`
4. **Key Operator Endpoints**: All under m3l, he2, cm2 interfaces
5. **Rate Limiting**: Not observed in decompiled code
6. **Request IDs**: Client-Time header used for request tracking
7. **Device Fingerprinting**: Extensive device headers sent (Device-Id, Device-Model, etc.)
8. **Location Required**: Many endpoints require lat/lng/radius
